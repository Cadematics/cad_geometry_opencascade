# 04 — Edge Topological Role

This exercise classifies B-rep edges according to their **topological role** within a CAD model.

It builds on the previous exercises:

```text
01_brep_inspector
        ↓
02_incidence_and_adjacency
        ↓
03_edge_classification
        ↓
04_edge_topological_role
```

The previous exercise identified the **geometric type** of an edge, such as:

```text
Line
Circle
Ellipse
Parabola
Hyperbola
Bezier
BSpline
```

This exercise asks a different question:

> **What role does the edge play in the B-rep topology?**

The current implementation classifies edges as:

```text
Boundary
Shared
Seam
Degenerate
Unknown
```

---

## 1. Geometry vs Topology

An important concept in CAD is the distinction between **geometry** and **topology**.

An edge contains both types of information.

```text
TopoDS_Edge
│
├── Topological information
│   ├── Incident faces
│   ├── Incident vertices
│   └── Topological role
│
└── Geometric information
    └── Underlying Geom_Curve
        ├── Line
        ├── Circle
        ├── Ellipse
        └── ...
```

For example, an edge can have:

```text
Curve type: Circle
```

while its topological role can be:

```text
Shared
```

or:

```text
Seam
```

These are independent properties.

---

## 2. Topological Roles

### Boundary

A boundary edge has only one incident face.

Conceptually:

```text
Face A
  │
  └── Edge
```

Boundary edges commonly occur on open shells or surfaces with free boundaries.

The program identifies this case when an edge has exactly one incident face occurrence.

---

### Shared

A shared edge connects two or more **distinct faces**.

For example:

```text
Face A
   │
   └── Edge ─── Face B
```

An ordinary edge inside a closed solid will typically be shared by two faces.

Example:

```text
Edge 1
  Topological role: Shared
  Vertices: V1 V2
  Faces: F1 F2
```

Because:

```text
F1 != F2
```

the edge is classified as `Shared`.

---

### Seam

A seam edge occurs when the **same face occurs on both sides** of an edge.

For example:

```text
Edge
 ├── F7
 └── F7
```

This commonly occurs on periodic surfaces such as cylinders.

A cylindrical surface wraps around in its angular parameter, so its parameterization can contain a seam.

Example from `cube_hole.step`:

```text
Edge 15
  Topological role: Seam
  Vertices: V10 V8
  Faces: F7 F7
```

The two face occurrences refer to the same topological face, so this is classified as a seam rather than a shared edge.

---

### Degenerate

A degenerate edge is explicitly marked as degenerated by OpenCASCADE.

The program checks this using:

```cpp
BRep_Tool::Degenerated(edge)
```

A degenerate edge can occur when an edge collapses to a point in the underlying geometry.

---

### Unknown

`Unknown` is used when the available topology does not fit the current classification rules.

For example, an edge with no associated faces cannot be classified as a normal boundary, shared, or seam edge.

---

## 3. Classification Logic

The program first constructs the edge-to-face incidence relationship:

```text
Edge → Faces
```

using:

```cpp
TopExp::MapShapesAndAncestors(
    shape,
    TopAbs_EDGE,
    TopAbs_FACE,
    edgeFaceMap
);
```

Each edge is then classified according to its topology.

The logic is:

```text
                    Edge
                      │
             Is it degenerate?
                /           \
              Yes            No
               │              │
          Degenerate      Count faces
                              │
                       ┌──────┼──────┐
                       │      │      │
                       0      1      >1
                       │      │       │
                    Unknown Boundary  Compare
                                      faces
                                        │
                              ┌─────────┴─────────┐
                              │                   │
                         Same face          Different faces
                              │                   │
                            Seam                Shared
```

---

## 4. Face Identity

Simply counting the number of incident face occurrences is not sufficient.

Consider:

```text
Faces: F1 F2
```

These are two different faces:

```text
F1 != F2
```

so the edge is `Shared`.

But:

```text
Faces: F7 F7
```

contains two occurrences of the **same face**.

Therefore it is a `Seam`.

The program checks actual face identity using:

```cpp
face.IsSame(existing)
```

rather than relying only on the number of face occurrences.

This distinction is important when working with OpenCASCADE B-reps.

---

## 5. Example: Cube With Cylindrical Hole

The model contains 15 unique edges.

The resulting classification is:

```text
Shared: 14
Seam:    1
```

The seam is:

```text
Edge 15
  Topological role: Seam
  Vertices: V10 V8
  Faces: F7 F7
```

The two circular edges of the hole, however, are shared edges:

```text
Edge 10
  Topological role: Shared
  Vertices: V8 V8
  Faces: F3 F7
```

and:

```text
Edge 14
  Topological role: Shared
  Vertices: V10 V10
  Faces: F5 F7
```

This demonstrates an important point:

```text
Geometric type ≠ Topological role
```

A circular edge is not automatically a seam.

Its role depends on how it is used by the B-rep topology.

## 6. Example: PLATE.STEP

The `PLATE.STEP` model contains:

```text

```

The classification result is:

```text

```

No boundary, seam, or degenerate edges were detected in this model.

Each edge connects two distinct faces.

## 7. Running the Program

The program accepts any STEP file as a command-line argument.

### General usage

```bash
./edge_topological_role path/to/model.step
```

For example:

```bash
./edge_topological_role ../../models/cube_hole.step
```

or:

```bash
./edge_topological_role ../../models/PLATE.STEP
```

The program is not tied to either model and can be used with another STEP file:

```bash
./edge_topological_role /path/to/another/model.step
```

## 9. Output Format

The program reports each edge as:

```text
Edge N
  Topological role: ROLE
  Vertices: V...
  Faces: F...
```

followed by a summary:

```text
SUMMARY
=======
Seam: 1
Shared: 14
```

The IDs are generated using OpenCASCADE indexed topology maps.

They provide stable identifiers within the loaded B-rep and allow edges, faces, and vertices to be related across the analysis.

---

## 10. Implementation

The main topology maps are constructed with:

```cpp
TopTools_IndexedMapOfShape edgeMap;
TopTools_IndexedMapOfShape vertexMap;
TopTools_IndexedMapOfShape faceMap;

TopExp::MapShapes(
    shape,
    TopAbs_EDGE,
    edgeMap
);

TopExp::MapShapes(
    shape,
    TopAbs_VERTEX,
    vertexMap
);

TopExp::MapShapes(
    shape,
    TopAbs_FACE,
    faceMap
);
```

The edge-to-face relationship is constructed using:

```cpp
TopTools_IndexedDataMapOfShapeListOfShape edgeFaceMap;

TopExp::MapShapesAndAncestors(
    shape,
    TopAbs_EDGE,
    TopAbs_FACE,
    edgeFaceMap
);
```

This provides the topology needed to determine the role of each edge.

## 11. Why This Matters for CAD Geometry

Curve classification alone does not describe the complete meaning of an edge.

For CAD reasoning, we need to combine:

```text
Geometry
    +
Topology
    +
Connectivity
```

For example:

```text
Edge
├── Curve: Circle
├── Vertices: V8 V8
├── Faces: F3 F7
└── Role: Shared
```

This structured information can later support higher-level reasoning such as:

* feature recognition
* hole detection
* pocket detection
* fillet detection
* chamfer detection
* shell analysis
* face adjacency
* B-rep graph construction
* CAD similarity
* geometric reasoning

## 13. Current Limitations

This exercise intentionally performs only basic topological classification.

It does not yet determine:

* convex vs concave edges
* dihedral angles
* tangent edges
* geometric continuity
* feature boundaries
* holes
* pockets
* fillets
* chamfers
* manufacturing features

These require geometric relationships between the edge and its incident faces.
